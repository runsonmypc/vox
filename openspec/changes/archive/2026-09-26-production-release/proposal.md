## Why

Vox is about to become public as v1.0.0 (GPL-3.0-only), installed by people who never read its code. A full review before release found problems that a private tool could live with and a public one cannot. Dictations could be lost or billed twice. Screen hints could send secrets on screen, such as API keys, to OpenAI. Logs in `/tmp` held what users said. The clipboard came back without images or files. A bad `config.toml` put the login service into a restart loop. There was no way to install a release, remove Vox, or check what was installed. This change records how the production-readiness round fixed those problems. The work was done in three waves of parallel groups, following the owner decisions dated 2026-09-26, and ends with two owner decisions on privacy.

## What Changes

- **Recording limit**: a recording that reaches `[audio] max_recording_seconds` (default 900 s) stops by itself and is transcribed and pasted like a normal stop. A new tray submenu, Recording Limit, offers 5, 10, 15, 30 and 60 minutes and saves the choice. **BREAKING**: before, a recording ran past the limit and the audio after the limit was silently dropped when the user stopped.
- **Uploads**: batch uploads are 16 kHz mono PCM16, and every downsampling path uses a band-limiting filter. A recording too large for one upload (about 13 minutes) is split at pauses, the parts are transcribed in order, and the texts are joined with a space. A part in which nothing is audible is not uploaded. If a part fails partway, the text already transcribed is saved to history and the tray says so, or it is pasted when history cannot keep it.
- **Billed work is never thrown away**: a transcript whose paste fails is still saved to history. Streaming waits for the server's final transcript for as long as it takes, and falls back to batch only on an error or a closed connection. Vox's own retry loop, which stacked on top of the OpenAI SDK's, is removed.
- **Screen hints** (`[context] screen`, default on): Vox captures only the focused window, never the whole display. Secret-looking tokens, including passwords in URLs, on command lines and after password-like names, are removed before any word is sent. On Linux, local whisper.cpp mode gives `whisper-cli --prompt` only the configured prompt and the dictionary words, never window-title or screen words (other accounts can read its command line), and captures nothing. Streaming sends the same filtered keyword list as batch instead of raw `Window:`/`Screen:` prompt lines. With the setting off, no window or screen words go to any provider, and no capture runs, so macOS never asks for Screen Recording.
- **Clipboard**: after a paste Vox restores the whole previous clipboard (every pasteboard type on macOS, the most useful target on X11), for every kind of app. On macOS Vox's temporary dictation write is marked transient and kept to this Mac. A copy that a password manager marks as a password is restored for this Mac only on macOS, and left off the clipboard on Linux, where it could only come back unmarked. Pasting works with any keyboard layout.
- **Logs**: transcript and snippet text is logged only at DEBUG (`vox -v`). **BREAKING**: INFO logs no longer contain what was said. **BREAKING**: on macOS, the log moves from `/tmp/vox.std*.log` to `~/Library/Logs/Vox/vox.log`, which only the user can read. It is cleared at startup once it passes 10 MiB.
- **Configuration errors**: `config.toml` is type- and range-checked. If it cannot be loaded at startup, Vox starts on defaults but refuses to record, and the tray says "Settings file has an error". Once the file is fixed, the change applies without a restart. **BREAKING**: values that used to load loosely, such as `level = "0.5"` or `level = 50`, now block dictation until they are fixed. A whisper.cpp setup that cannot run no longer stops Vox from starting.
- **Tray**: the status line names the most urgent problem (settings file, API key, transcription mode, then a notice such as Wayland, a silent microphone, missing Accessibility access, or a partial transcription). The Input Device menu is built from a device list the daemon rescans, and a pick is remembered by name.
- **History**: dictations can be deleted one at a time, or all at once with Clear History. Deleted text is overwritten in the database file, which only the user can read. Search folds case for every alphabet. The list shows the newest 200 dictations. History records the provider that actually produced the text.
- **Startup**: a per-user lock directory replaces `/tmp/vox-daemon.lock`. A second instance exits 0. `vox --version` prints the version. An `OPENAI_API_KEY` override is removed from Vox's environment, so processes Vox starts don't inherit it. Key migration now handles a symlinked `.env` and a `.env` that holds several keys, and an unreadable `.env` no longer stops Vox. SIGTERM, from a service stop, a logout or an update, quits the way Quit does and restores a lowered volume.
- **Custom sounds**: optional overrides are read from `~/.config/vox/sounds/<name>.wav`. **BREAKING**: WAV files in the checkout's `sounds/` directory are no longer used, and that directory is removed.
- **Release packaging**: a release tarball plus `install.sh` for macOS and Linux, a `curl … | bash` bootstrap that verifies `SHA256SUMS`, `install.sh --uninstall`, a `.deb` for Ubuntu 24.04 (amd64 and arm64) that starts Vox at login for every user, hash-locked dependencies with no compiler needed, CI on free GitHub-hosted runners only, and a tag-driven release workflow. **BREAKING**: `start.sh` is removed, and development uses `uv run vox`. The service files move to `packaging/`. The installer refuses to run as root, and on Linux it needs Python 3.12 or 3.13 as `/usr/bin/python3`. On Linux, `install.sh` and the `.deb` also need `xprop` (x11-utils). The macOS installer never writes into or removes an app bundle it did not create, and the installer ends by printing the full `vox` path, with a warning when `~/.local/bin` is not on `PATH`.
- Internal cleanups with no user-visible effect: the `WhisperTranscriber` alias, `SoundPlayer.play(blocking=)` and the unused `[styles]` table are removed, and mode rules live in one module.

## Capabilities

### New Capabilities
- `release-packaging`: how Vox is installed, updated, removed and released. Covers the per-user installer (moved here from `desktop-frontend`) with its system packages, its guard against another app named Vox on macOS and its closing `PATH` check, the release bootstrap, uninstall, the Debian package, hash-locked dependencies, the Linux login service, CI, and the release workflow.
- `screen-context`: the `[context] screen` setting, capture of the focused window only, secret filtering, when capture runs, and exactly which words each transcription mode sends to OpenAI.
- `dictation-pipeline`: what happens between the hotkey and the paste, across modes. Covers the recording limit and its tray submenu, the upload format and split uploads, resampling, request handling, paste failure, clipboard restore, logging without dictated text, configuration and mode errors, silent-microphone detection, device rescans, hotkey names and sounds, and quitting on SIGTERM.

### Modified Capabilities
- `desktop-frontend`: status-line problems; the device menu built from a snapshot and remembered by name; the active mode that cannot run; history kept on paste failure, private and erasable; history window delete, Clear History and the 200-row cap; a vocabulary window that changes nothing while `config.toml` does not load. The per-user installation requirement moves to `release-packaging`.
- `streaming-transcription`: stateful band-limited 24 kHz audio; the filtered keyword list with no raw screen text; waiting for completion with no deadline; batch fallback on server errors, capturing at fallback time the window that was focused when the recording started.
- `macos-support`: the per-user directory lock with exit 0 or 78; focused-window detection through Accessibility and the CGWindowID; a transient, layout-aware paste; a clipboard a password manager marks as concealed restored for this Mac only; volume restored on every exit path, including SIGTERM; capture of the focused window only; microphone diagnostics at runtime; a LaunchAgent with private logs and absolute paths.
- `double-tap-cancel`: the cancel sound follows `[sounds] enabled` live and can be overridden; cancelling stops a local whisper.cpp run; a paste already under way completes and restores the clipboard.
- `api-key`: the environment override is hidden from child processes; migration handles several keys in `.env`, a symlinked `.env`, and a `config.toml` key when there is no keychain, and leaves the keychain alone when there is nothing to move; an unreadable `.env` is reported instead of stopping Vox; the key window refuses characters that cannot be part of a key.

## Impact

- Code: nearly every module under `vox/` changed (30 of its 37 files by the end of wave 1). The largest changes are in `daemon.py` (a small state machine class with one session per recording), `audio.py`, `transcribe.py`, `streaming.py`, `injector.py`, `window.py`, `config.py`, `__main__.py`, `history.py` and `ui/tray.py`, and in the history windows.
- Packaging: new `packaging/{linux,macos,deb}`, `scripts/`, `.github/workflows/{ci,release}.yml`, `requirements.lock`, `LICENSE`, `CHANGELOG.md`, `SECURITY.md` and `RELEASING.md`. `install.sh` is rewritten, and `start.sh` and `sounds/` are removed.
- Dependencies: `websockets>=14` (the version whose `connect` takes `additional_headers`). The resampler uses numpy only, with no new dependencies. A `build` dependency group pins setuptools, and `uv.lock` is written by uv 0.12.19.
- User data: the macOS log moves (old `/tmp` logs owned by the user are deleted), the history database and its directory are tightened to 0600 and 0700, and a plain-text key is migrated as described in `api-key`.
- Services: `vox.service` has `RestartPreventExitStatus=78` and `UMask=0077`. The LaunchAgent restarts Vox only after a crash.
- Tests: the test functions roughly doubled, from 279 at the start of the round to 565 at the end of wave 1 (727 collected tests pass on macOS), and to about 680 at 5011b11 (955 collected tests pass on macOS). Tests are isolated from the real keychain, `HOME`, the network and GTK 3. GTK 4 window tests run in their own process on Linux.
